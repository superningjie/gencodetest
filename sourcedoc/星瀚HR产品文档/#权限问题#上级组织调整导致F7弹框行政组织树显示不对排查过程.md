## 适用版本

星瀚v7.0及以上版本

## 1 问题描述

用户所在的六级组织的上级组织调整完之后，用户行政组织树还是显示原来的，并且列表数据没有数据。

![上传图片](https://vip.kingdee.com/download/010053c3b1f2c028461aa040ae6301d10407.png)

## **2 原因分析（可选）**

a. 先通过monitor日志查询getDataRule获取权限接口返回的行政组织数据。

![上传图片](https://vip.kingdee.com/download/0100139ca5e4fa9745cfb79e3e28cd47352b.png)

b. 通过行政组织id查询boid

select * from t_haos_adminorg where fnumber = '0629001'

select * from t_haos_adminorg where fboid = 486095482586692608 and fiscurrentversion = '1'

c. 通过boid查询t_haos_adminstruct和t_haos_orgteamstruct两张表的数据，以及长编码是否一致

select * from t_haos_adminstruct where fadminorgid = 486095482586692608 and fiscurrentversion = '1'

select * from t_haos_orgteamstruct where forgteamid = 486095482586692608 and fiscurrentversion = '1'

## 3 解决方法

最后发现组织发生变更之后，t_haos_orgteamstruct没有生成对应的版本数据，组织长编码还是以前的导致，处理方式是对组织数据进行修复。
