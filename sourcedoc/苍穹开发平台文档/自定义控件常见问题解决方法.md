    # 1 用户场景
    随着客户个性化需求的日益增长，自定义控件扮演着越来越重要的角色。可以说，自定义控件是苍穹扩展的重要手段。目前，各业务项目组或者客户伙伴基本上都有自己的自定义控件，与之投入开发的人后端开发居多，导致开发过程中很少会自己分析并解决问题，因此本文将针对一些基本、常见的问题提出解决方案。
    # 2 功能介绍
    将教大家如何排查最基本、最常见的开发过程中遇到的自定义控件相关问题(报错等)
    遇到问题可以先看浏览器控制台是否有报错
    
    首先，动动手指头，按键盘“**F12**”将浏览器的 **开发者工具** 调出来（一般推荐chrome浏览器），点击并切换到该工具的"Console"面板
    ![image.png](/download/0100c714225699e6432db988e3d911886419.png)
    
    可以说，大多数的错误都可以在这里看到，但是有一些比较棘手的问题，可能需要由平台的老师来解决。
    那么接下来，针对控制台的报错，将提供对应的分析以及解决问题的办法。
    ## 2.1 404错误
    这个错误在控制台里类似提示效果如下(注意"**404**"关键字)：
    ![image.png](/download/01005f88260d710e458abe07c0bcbbb5de7f.png)
    
    从报错信息中可以看出来，是自定义控件的index.js文件没有找到。没有找到资源文件的原因基本是以下几点：
    **1、请求路径错误**
    以下内容包含正确和错误的路径示例(以及错误的原因)：
    错误路径：
    [https://feature.kingdee.com:2024/baseline_a/isv/kdtest/cq/](https://feature.kingdee.com:2024/baseline_a/isv/kdtest/cq/undefined/index.js?v=1)[undefined](https://feature.kingdee.com:2024/baseline_a/isv/kdtest/cq/undefined/index.js?v=1)[/index.js?v=1](https://feature.kingdee.com:2024/baseline_a/isv/kdtest/cq/undefined/index.js?v=1)（路径中有undefined）
    [https://feature.kingdee.com:2024/baseline_a/isv/kdtest/helloworld/index.js?v=1](https://feature.kingdee.com:2024/baseline_a/isv/kdtest/helloworld/index.js?v=1)（路径拼接错误，缺少isvId、moduleId、schemaId其中一个或者多个）
    正确路径：
    [https://feature.kingdee.com:2024/baseline_a/isv/kdtest/cq/helloworld/index.js?v=1](https://feature.kingdee.com:2024/baseline_a/isv/kdtest/cq/helloworld/index.js?v=1)
    [https://feature.kingdee.com:2024/baseline_a/isv/kdtest/fi/helloworld/index.js?v=1](https://feature.kingdee.com:2024/baseline_a/isv/kdtest/fi/helloworld/index.js?v=1)
    **2、文件不在isv目录下所在领域对应的控件方案文件夹里**
    如果是第一个原因造成的，可以直接联系总部前端技术服务部（或在自定义控件相关沟通群反馈）
    如果是第二个原因造成的，你可以按照下面思路排查：
    ① 如果是以上传zip包方式上传控件方案的，检查zip包的目录结构。注意，打包时，index.js一定是在包的根目录下的，即打开zip包第一眼看到的一定要有**index.js**；
    ② 如果按照第一点排查解决之后还是有问题，你就需要检查一下上传成功后，静态资源目录下有没有控件方案及其资源，一般在 **webapp/isv/开发商标识/领域标识/控件方案id/** 下（非zip包上传控件方案方式，即本地开发方式，此排查方式也适用）；
    ③ 如果按照第二点排查解决之后还是有问题，那么需要检查一下Nginx的配置了，也有可能是代理的资源路径不正确；
    **3、没有预置脚本预插数据（如果不知道怎么写预置脚本可以询问部门架构师）**
    如果按照以上还没有找到问题，请联系前端技术服务部（或在自定义控件相关沟通群反馈）

    ## 2.4 没有报错但就是啥也没有
    一定要记住，出现这个问题的
    前提是没有404错误、register错误、语法错误！！！
    前提是没有404错误、register错误、语法错误！！！
    前提是没有404错误、register错误、语法错误！！！
    重要的事情说三遍！不要因为看了此小节标题直接跳过前面几个小节！
    
    这种错误就是在UI渲染时出现了问题，除了React或者Vue写法的自定义控件外，有可能在这个地方出现问题：
    ![image.png](/download/010010089a0d1d3e43ba8eb90af535f280ea.png)
    
    **model.dom.innerHTML = result**这句代码的意思是将**html**字符串赋值给自定义控件的**DOM**节点，也就是在这地方啥都没有才会导致渲染时啥都没有。
    如果真的啥都没有，可以检查下面这三个地方：
    **1、html模板文件**
    **2、后端返回数据**
    **3、路由匹配问题（开发vue或者react时候，仍然使用路由去匹配页面路由规则，其实是不需要的）**
    针对第一点，可以参照一下 **art-template** 的语法，参考：[/tolink?target=https://www.jianshu.com/p/d8d8e19157e0](/tolink?target=https://www.jianshu.com/p/d8d8e19157e0)
    如果 **html** 模板没有问题，你需要检查后端请求返回的数据是不是正确的，可以打开浏览器开发者工具，切到“**Network**”面板，找到相关请求返回的服务端数据，例如：

    ## 2.7 同页面多控件方法引入异常
    在同个页面中存在多个不同的控件，控件A总是调用到了控件B的JS中的同名函数。原因是自定义控件中的**KDApi.loadFile**也是通过创建**script**标签在页面中引入的，按照**script**的引用顺序，后面的方法名会把前面同名的方法名覆盖。排查以下
    1、可以尝试在不同的控件方案中使用不同的方法名
    2、如果按照以上还没有解决问题，请联系前端技术服务部（或在自定义控件相关沟通群反馈）。

    ## 2.12 vuex等全局状态管理导致多个页签自定义控件数据共享
    全局状态管理例如 Vuex 等的数据存储在 **全局的单例模式**中，而 Vuex Store 不是 Vue 实例本身，而是一个独立的 JavaScript 对象。即使在同一个页面中创建了多个 Vue 实例，它们如果使用的是同一个 Vuex Store 实例，那么它们访问的数据就是共享；
    解决方案：
    通过传入的`pageId`或其他唯一标识给不同实例的`store`数据添加命名空间
    ```
    import Vue from 'vue'
    import Vuex from 'vuex'
    
    Vue.use(Vuex)
    
    export function createStore(moduleName) {
      return new Vuex.Store({
        modules: {
          [moduleName]: {
            namespaced: true,
            state: {
              count: 0
            },
            mutations: {
              increment(state) {
                state.count++
              }
            }
          }
        }
      })
    }
    
    // app
    import Vue from 'vue'
    import { createStore } from './store'
    
    const storeA = createStore('appA')
    
    new Vue({
      el: '#app',
      store: storeA,
      template: `<div>
                  <p>App A Count: {{ $store.state.appA.count }}</p>
                  <button @click="$store.commit('appA/increment')">Increment A</button>
                </div>`
    })
    
    ```
    参考：[vue2-vuex.zip](http://fd.kingdee.com:9001/file/attach/67f760e3d1a4ad00c4610846)
    
    ## 2.13 自定义控件样式隔离
    
    * 不少小伙伴反馈自定义控件中引入的第三方包中包含`reset.css`等样式重置文件，引入后会影响平台的样式，又或者希望在自定义控件中单独生效某些全局样式，怎么做可以和其他自定义控件or平台样式隔离，一下有几种方案可供选择；
    
    
    1. 新项目：使用[脚手架创建项目](https://vip.kingdee.com/knowledge/656865487539778816?specialId=194046086670543360&productLineId=29&isKnowledge=2&lang=zh-CN)，脚手架中默认集成样式隔离功能
    2. 旧项目：
    
        1. 方案一：
    
            * 在自定义控件根节点添加属性选择器，例如` <div>`
            * 在样式文件中使用`[data-control-name='vue3_control'] { css.... }`
    
    
    
        1. 方案二
    
            * 使用`postcss-prefix-selector`打包插件，对所有样式文件添加前缀
    
    
    
    ```
    // postcss.config.js
    module.exports = {
      plugins: [
        require('postcss-prefix-selector')({
          prefix: '[data-control-name="vue3_control"]',
          exclude: [/^::/, /^:root/, /^\.kd-custom-exclude/], // 排除:开头的浏览器标签
          transform: function (prefix, selector, prefixedSelector) {
            return prefixedSelector
          },
        }),
      ],
    }
    
    
    ```
    
    ## 2.14 自定义控件打包分包方案
    通过拆包可避免单入口文件体积过大而导致的加载时间过长，且平台标品对请求的资源大小有限制，原厂的自定义控件需要针对打包后的资源体积进行拆分，二开也可参考一下配置
    自定义控件脚手架已默认集成分包功能(2025/07/09)，在这个时间前创建的项目，可通过脚手架重新创建项目或者根据以下方案自行添分包配置。
    ```
    /* webpack.js 核心配置 */
    
    output: {
        path: path.resolve(__dirname, '../dist'),
        filename: 'index.js',
        clean: true,
        asyncChunks: true, // 启用异步代码分割
        chunkFilename: 'js/[name].[contenthash:8].js', // 异步代码分割的文件名格式
    },
    optimization: {
        sideEffects: true, // 启用副作用处理
        splitChunks: {
          chunks: 'async', // 只对异步加载的模块进行代码分割
          minSize: 20000,
          maxSize: 1000000, // 最大文件体积，1000000 = 1m
          cacheGroups: {
            vendors: {
              test: /[\\/]node_modules[\\/]/,
              name: 'vendors',
              priority: 10,
              minSize: 0, // 不限制最小大小
            },
          },
        }
    },
    
    
    ```
    react项目懒加载优化示例：
    ```
    import { lazy } from "react";
    const App = lazy(() => import(/* webpackChunkName: 'App' */ "./App"));
    export { App };
    
    /* index.js */
    <Suspense fallback={null}>
      <App />
    </Suspense>
    
    
    ```
    vue项目懒加载优化示例：
    ```
    import { defineAsyncComponent } from "vue";
    const App = defineAsyncComponent(
      () => import(/* webpackChunkName: "App" */ "./App.vue")
    );
    export { App };
    
    /* Index.vue 入口文件 */
    <template>
      <Suspense>
        <template #default>
           <App />
        </template>
        <template #fallback></template>
      </Suspense>
    </template>
    
    <script setup lang="ts">
    import { App } from "@/components/index";
    </script>
    ```

## 2.12 vuex等全局状态管理导致多个页签自定义控件数据共享

全局状态管理例如 Vuex 等的数据存储在 **全局的单例模式** 中，而 Vuex Store 不是 Vue 实例本身，而是一个独立的 JavaScript 对象。即使在同一个页面中创建了多个 Vue 实例，它们如果使用的是同一个 Vuex Store 实例，那么它们访问的数据就是共享；  
解决方案：  
通过传入的`pageId`或其他唯一标识给不同实例的`store`数据添加命名空间
    
    
    import Vue from 'vue'
    import Vuex from 'vuex'
    
    Vue.use(Vuex)
    
    export function createStore(moduleName) {
      return new Vuex.Store({
        modules: {
          [moduleName]: {
            namespaced: true,
            state: {
              count: 0
            },
            mutations: {
              increment(state) {
                state.count++
              }
            }
          }
        }
      })
    }
    
    // app
    import Vue from 'vue'
    import { createStore } from './store'
    
    const storeA = createStore('appA')
    
    new Vue({
      el: '#app',
      store: storeA,
      template: `<div>
                  <p>App A Count: {{ $store.state.appA.count }}</p>
                  <button @click="$store.commit('appA/increment')">Increment A</button>
                </div>`
    })

## 2.14 自定义控件打包分包方案

通过拆包可避免单入口文件体积过大而导致的加载时间过长，且平台标品对请求的资源大小有限制，原厂的自定义控件需要针对打包后的资源体积进行拆分，二开也可参考一下配置  
自定义控件脚手架已默认集成分包功能(2025/07/09)，在这个时间前创建的项目，可通过脚手架重新创建项目或者根据以下方案自行添分包配置。
    
    
    /* webpack.js 核心配置 */
    
    output: {
        path: path.resolve(__dirname, '../dist'),
        filename: 'index.js',
        clean: true,
        asyncChunks: true, // 启用异步代码分割
        chunkFilename: 'js/[name].[contenthash:8].js', // 异步代码分割的文件名格式
    },
    optimization: {
        sideEffects: true, // 启用副作用处理
        splitChunks: {
          chunks: 'async', // 只对异步加载的模块进行代码分割
          minSize: 20000,
          maxSize: 1000000, // 最大文件体积，1000000 = 1m
          cacheGroups: {
            vendors: {
              test: /[\\/]node_modules[\\/]/,
              name: 'vendors',
              priority: 10,
              minSize: 0, // 不限制最小大小
            },
          },
        }
    },
    
    
    

react项目懒加载优化示例：
    
    
    import { lazy } from "react";
    const App = lazy(() => import(/* webpackChunkName: 'App' */ "./App"));
    export { App };
    
    /* index.js */
    <Suspense fallback={null}>
      <App />
    </Suspense>

## 2.12 vuex等全局状态管理导致多个页签自定义控件数据共享

全局状态管理例如 Vuex 等的数据存储在 **全局的单例模式** 中，而 Vuex Store 不是 Vue 实例本身，而是一个独立的 JavaScript 对象。即使在同一个页面中创建了多个 Vue 实例，它们如果使用的是同一个 Vuex Store 实例，那么它们访问的数据就是共享；  
解决方案：  
通过传入的`pageId`或其他唯一标识给不同实例的`store`数据添加命名空间
    
    
    import Vue from 'vue'
    import Vuex from 'vuex'
    
    Vue.use(Vuex)
    
    export function createStore(moduleName) {
      return new Vuex.Store({
        modules: {
          [moduleName]: {
            namespaced: true,
            state: {
              count: 0
            },
            mutations: {
              increment(state) {
                state.count++
              }
            }
          }
        }
      })
    }
    
    // app
    import Vue from 'vue'
    import { createStore } from './store'
    
    const storeA = createStore('appA')
    
    new Vue({
      el: '#app',
      store: storeA,
      template: `<div>
                  <p>App A Count: {{ $store.state.appA.count }}</p>
                  <button @click="$store.commit('appA/increment')">Increment A</button>
                </div>`
    })

## 2.13 自定义控件样式隔离

  * 不少小伙伴反馈自定义控件中引入的第三方包中包含`reset.css`等样式重置文件，引入后会影响平台的样式，又或者希望在自定义控件中单独生效某些全局样式，怎么做可以和其他自定义控件or平台样式隔离，一下有几种方案可供选择；


  1. 新项目：使用[脚手架创建项目](https://vip.kingdee.com/knowledge/656865487539778816?specialId=194046086670543360&productLineId=29&isKnowledge=2&lang=zh-CN)，脚手架中默认集成样式隔离功能

  2. 旧项目：

     1. 方案一：

        * 在自定义控件根节点添加属性选择器，例如` <div>`
        * 在样式文件中使用`[data-control-name='vue3_control'] { css.... }`
     2. 方案二

        * 使用`postcss-prefix-selector`打包插件，对所有样式文件添加前缀


    
    
    // postcss.config.js
    module.exports = {
      plugins: [
        require('postcss-prefix-selector')({
          prefix: '[data-control-name="vue3_control"]',
          exclude: [/^::/, /^:root/, /^\.kd-custom-exclude/], // 排除:开头的浏览器标签
          transform: function (prefix, selector, prefixedSelector) {
            return prefixedSelector
          },
        }),
      ],
    }
    
    
    

## 2.14 自定义控件打包分包方案

通过拆包可避免单入口文件体积过大而导致的加载时间过长，且平台标品对请求的资源大小有限制，原厂的自定义控件需要针对打包后的资源体积进行拆分，二开也可参考一下配置  
自定义控件脚手架已默认集成分包功能(2025/07/09)，在这个时间前创建的项目，可通过脚手架重新创建项目或者根据以下方案自行添分包配置。
    
    
    /* webpack.js 核心配置 */
    
    output: {
        path: path.resolve(__dirname, '../dist'),
        filename: 'index.js',
        clean: true,
        asyncChunks: true, // 启用异步代码分割
        chunkFilename: 'js/[name].[contenthash:8].js', // 异步代码分割的文件名格式
    },
    optimization: {
        sideEffects: true, // 启用副作用处理
        splitChunks: {
          chunks: 'async', // 只对异步加载的模块进行代码分割
          minSize: 20000,
          maxSize: 1000000, // 最大文件体积，1000000 = 1m
          cacheGroups: {
            vendors: {
              test: /[\\/]node_modules[\\/]/,
              name: 'vendors',
              priority: 10,
              minSize: 0, // 不限制最小大小
            },
          },
        }
    },
    
    
    

react项目懒加载优化示例：
    
    
    import { lazy } from "react";
    const App = lazy(() => import(/* webpackChunkName: 'App' */ "./App"));
    export { App };
    
    /* index.js */
    <Suspense fallback={null}>
      <App />
    </Suspense>
    
    
    

vue项目懒加载优化示例：
    
    
    import { defineAsyncComponent } from "vue";
    const App = defineAsyncComponent(
      () => import(/* webpackChunkName: "App" */ "./App.vue")
    );
    export { App };
    
    /* Index.vue 入口文件 */
    <template>
      <Suspense>
        <template #default>
           <App />
        </template>
        <template #fallback></template>
      </Suspense>
    </template>
    
    <script setup lang="ts">
    import { App } from "@/components/index";
    </script>
